# Canvas 연동 PoC — 검증 기획과 실행 기준

이 문서는 첫 기술 검증에서 **무엇을 확인할지** 정한 실행 기준이다. 2026-09-27의 실제 Sandbox 결과와 남은 문제는 [POC_RESULTS.md](POC_RESULTS.md)에 기록했다. 전체 판정은 **부분 통과**다.

## 검증 목적

사용자가 기존 Canvas를 열고 브러시로 카드 위에 그린 뒤 화면을 이동·확대하고 재실행해도 그림이 같은 자리에 남는지 확인한다. 그림 때문에 카드 조작과 대형 Canvas 탐색이 무너지지 않는지도 함께 본다.

## 최소 사용 시나리오

`Canvas 열기 → Drawing Tool 선택 → 빈 공간과 카드 위에 시험용 선 그리기 → Space/휠로 이동·확대 → Selection Tool로 카드 이동 → 저장·재실행 → 그림과 카드 확인`

PoC에는 고급 브러시, 색 혼합, 프리셋 관리, 전체 레이어 시스템, Photoshop Import를 넣지 않는다. 단순한 시험용 선으로 Canvas 연동의 성립 여부를 본다.

이 첫 검증에서 Selection Tool은 카드 조작으로 돌아가는지까지만 확인한다. 사용자가 결정한 사각형·올가미 그림 선택 도구는 후속 기본 그리기 단계에서 별도로 검증한다.

## 시험 환경과 순서

원본 Vault가 아닌 **Windows의 독립 Obsidian Sandbox**에서 시험한다. 먼저 Obsidian 버전과 Canvas 화면 상태를 기록하고, 시험 Canvas와 그림 데이터의 백업을 만든다. PoC는 제품 전체 구현이 아니라 시험용 입력·표시·저장 경로만 갖춘다. 시험 실패가 사용자 자료에 영향을 주지 않도록 시험 Canvas만 사용한다.

1. 카드·이미지·그룹이 있는 작은 Canvas를 연다. 기능을 끈 상태에서 카드 선택·이동, Space/휠 이동, 휠 확대가 정상인지 먼저 확인한다.
2. 시험용 선을 빈 공간과 카드 위에 그린다. 카드 입력 충돌, 그림의 앞쪽 표시, 포인터를 놓은 뒤의 결과를 관찰한다.
3. 같은 선을 화면 이동·확대·축소 전후에 비교한다. 다시 Selection Tool을 골라 카드 이동을 확인한다.
4. Canvas를 전환·닫았다 다시 열고, Obsidian도 재시작한다. 두 경우 모두 선이 같은 위치에 돌아오는지 확인한다.
5. 시험 Canvas를 Obsidian 내부 `.trash`와 Windows 시스템 휴지통으로 각각 보낸 뒤 복원한다. 사용자 결정대로 두 방식 모두 카드와 그림이 함께 돌아오는지 확인한다.
6. 플러그인을 끄고 다시 켜거나 제거·재설치한 뒤 같은 시험 Canvas를 연다. 그림 데이터가 사라지지 않고 재활성화 후 다시 보이는지 확인한다. 미설치 상태의 화면은 별도로 기록한다.
7. 작은 Canvas보다 카드·이미지·그룹과 그림이 많은 별도 시험 Canvas에서 기능을 켜고 끈 상태를 비교한다. Pan·Zoom·카드 이동·저장 중 멈춤 또는 눈에 띄는 지연을 확인하고, 측정 가능한 값만 수치로 기록한다.

기준 Canvas의 정확한 크기, 화면 확대율, 반복 횟수와 성능 판정 수치는 Sandbox 환경을 확인한 뒤 실행 기록에 명시한다. 임의의 수치를 제품 보장값으로 삼지 않는다.

## 관찰 항목과 통과 결과

| 항목 | 실제 앱에서 확인할 결과 |
|---|---|
| 전체 Canvas | 별도 그림판 화면 없이 현재 Canvas의 빈 위치와 카드 위에서 선을 그릴 수 있다. |
| 표시 순서 | 그림은 카드보다 앞에 보인다. 그림 레이어 간 순서는 후속 검증에서 다룬다. |
| 카드 충돌 | Drawing Tool로 카드 위를 드래그해도 카드 선택·이동이 일어나지 않는다. |
| 원래 조작 복귀 | Selection Tool로 바꾸면 카드 선택·이동이 다시 된다. |
| 좌표 | 이동·확대·축소 뒤에도 선이 카드·이미지와 같은 상대 위치에 남는다. |
| 저장·복원 | Canvas 전환과 Obsidian 재시작 뒤 선이 원래 위치에 나타난다. |
| 휴지통 복원 | 그림이 있는 시험 Canvas를 내부 `.trash` 또는 Windows 시스템 휴지통으로 보낸 뒤 복원하면 카드와 그림이 함께 돌아온다. 사용자 결정의 구현 가능성과 데이터 연결을 각각 확인한다. |
| 데이터 분리 | 선을 여러 개 추가해도 Canvas Node가 획 수만큼 늘어나지 않는다. |
| 기본 성능 | 같은 시험 Canvas에서 그리기 기능을 켜고 끈 상태의 Pan·Zoom·카드 조작 반응을 비교한다. 눈에 띄는 퇴보가 있으면 통과로 처리하지 않고 측정 근거를 남긴다. |

## 실행 전 기록할 조건

- 사용한 Obsidian 버전, OS, Sandbox Vault, Canvas 종류와 크기.
- 시험 전후 `.canvas` 및 별도 그림 데이터 상태.
- 휴지통으로 이동·복원할 때 원본과 복원본의 Canvas·그림 연결 상태. 영구 삭제 시점과 정리 방식은 이 시험 결과를 보고 별도로 정의한다.
- 카드·이미지 수와 그림 획 수. 대형 Canvas 비교 자료를 별도로 기록.
- 화면 이동·확대, 카드 조작, 재시작을 실제로 본 증거와 실패한 정확한 단계.
- 성능 수치는 실제로 측정한 경우에만 적고, 측정되지 않은 경우 체감 결과와 `미측정`을 분리.
- 각 시나리오를 `통과 / 부분 통과 / 실패 / 판정 불가`로 기록하고, 실패하면 사용자에게 보이는 차이와 재현 조건을 남긴다.

## 현재 공식 자료로 확인한 범위

Obsidian의 공개 [`canvas.d.ts`](https://github.com/obsidianmd/obsidian-api/blob/master/canvas.d.ts)는 Canvas의 Node·Edge 등 파일 데이터 형식을 정의한다. 이 파일만으로 Canvas 전체에 그리기를 얹거나 카드 입력을 제어하는 공개 API가 보장되는 것은 아니다. 플러그인 자료는 [Vault 이벤트와 리소스 정리](https://docs.obsidian.md/Plugins/Events), [파일 읽기·수정·휴지통 처리](https://docs.obsidian.md/Plugins/Vault)를 제공한다. 따라서 Canvas 화면 통합과 휴지통 복원 결과는 실제 앱에서 검증해야 한다.

## 판정과 다음 단계

2026-09-27 사용자 승인으로 진행 기준을 조정했다. 현재 부분 통과 결과를 바탕으로 기능 기획을 계속한다. 아래 통과 기준은 본 개발의 관련 기능 완료 판정에 적용하며, 모든 시험을 끝낼 때까지 기획을 막는 관문으로 사용하지 않는다. 대형 Canvas 최적화와 삭제 정리 등의 상세 시험은 해당 기능 개발 시 수행한다. 새로운 기획을 위해서는 결론에 영향을 주는 최소 실험만 한다.

- **통과:** 모든 필수 항목이 실제 앱에서 성립. 이후 기본 Drawing Engine과 남은 UX 기획을 진행할 수 있다.
- **부분 통과:** 일부만 성립. 미해결 항목을 남겨 두고 기획을 이어갈 수 있으나, 관련 기능의 구현 완료·배포 통과로 간주하지 않는다.
- **실패:** 제품 최상위 원칙 또는 P0 성능·데이터 안정성과 충돌. Canvas 연동 방식을 다시 검토한다.
- **판정 불가:** 실행 환경 또는 증거 부족으로 확인하지 못함. 이를 통과로 간주하지 않는다.

Canvas 연동이 통과한 뒤 Color Mixing의 시각적 결과와 CPU·GPU·메모리 비용을 별도 관문으로 다룬다. 세부 렌더링 방식과 저장 파일 형식은 이 PoC 기획에서 확정하지 않는다.
