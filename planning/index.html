02 / 앞으로의 전체 순서

사용 결과를 정하고, 필요한 부분을 검증하며 진행합니다

현재까지는 기존 자료 분류와 첫 Canvas 검증안 작성까지 진행했습니다. 다음 순서는 아래와 같습니다.

1

남은 사용자 결정 정리

복원·그림 선택·표시 순서·데이터 보존·첫 플랫폼을 정했습니다. 남은 사용자 결과도 필요한 때 하나씩 결정합니다. 진행 중

2

Canvas 검증 범위 확정

어떤 Obsidian 환경과 시험 자료에서 무엇을 확인할지, 통과 결과가 무엇인지 정합니다.

3

작은 Canvas 검증 실행

시험용 선으로 카드 위 그리기, 화면 이동·확대, 카드 조작 복귀, 저장·재실행, 기본 성능을 실제 앱에서 봅니다.

4

결과를 기획에 반영

통과하면 다음 기능으로 갑니다. 부분 통과·실패는 사용자에게 보이는 차이와 대안을 먼저 정합니다.

5

기본 그리기 상세 기획

지우개, 레이어, 도형·문자, 영역 선택, 복사·붙여넣기, 실행 취소를 실제 사용 순서로 연결합니다.

6

고급 기능 별도 검증

색 혼합의 품질·성능, Photoshop 브러시 호환, 화면 색 추출, Canvas 기록과의 Undo 통합을 각각 판정합니다.

7

최종 기획서 작성

확정·제외·미결정과 검증 결과, 화면 사용 흐름, 데이터 관계, 완료 조건을 한 문서로 묶습니다.

8

단계별 구현·실제 앱 확인·배포

기획을 기준으로 기능을 만들고 실제 Obsidian 화면과 동작을 확인한 뒤 필요한 릴리즈를 진행합니다.

예상 시간과 부담
초기 기획 정리의 Codex 작업 시간 추정은 35~55분이며, 사용자 답변 대기 시간은 포함하지 않습니다. Canvas PoC와 전체 개발의 시간은 시험 환경과 범위를 정한 뒤 추정합니다. 완성된 프로그램의 CPU·메모리·저장 공간·화면 반응성 비용은 아직 측정되지 않았습니다.
03 / 기존 자료 분류

정해진 경험과 기술 검증 대상을 분리합니다

아래 가로 막대는 진척률이나 성공률이 아닙니다. 각 묶음의 성격을 구분하는 도표입니다.

사용 경험 기준선
Canvas 직접 그리기 · 고정 UI · 기본 입력
기술 검증 목표
Canvas 연동 · 색 혼합 · 호환성
명시적 제외
별도 그림판 · 획마다 Node 생성 등
사용자 결정 필요
플러그인 안내 · 충돌 범위 등

막대 길이는 비교 수치가 아닌 시각적 구분입니다. 기능 수나 완료 비율을 나타내지 않습니다.

기존 문서상 확정

Canvas에서 바로 그리기

카드와 이미지가 놓인 같은 공간에 그림을 그립니다. 그리는 동안 카드 입력을 막고, Selection Tool에서는 원래 카드 조작으로 돌아갑니다.

왼쪽 도구 막대와 브러시 목록, 오른쪽 레이어 목록의 위치도 기준선입니다.

목표 + 검증 필요

고급 그리기 경험

색 혼합, Photoshop 브러시 가져오기, 화면 전체에서 색 추출, Canvas와 이어지는 Undo 기록은 목표입니다.

최종 품질·지원 범위·구현 가능 여부는 각각 확인해야 합니다.

현재 제외

만들지 않는 방식

별도 그림판 영역, 그린 획 하나마다 Canvas 항목 생성, 레이어 복제, 도형 채우기 등은 기존 자료의 제외 항목입니다.

새 기능 제안이 이 항목을 다시 필요로 하면 충돌로 표시합니다.

04 / 첫 번째 기술 검증 계획

시험용 선 하나로 Canvas 연동을 확인합니다

고급 브러시를 만들기 전에, 가장 기본적인 그림이 기존 Canvas와 함께 작동하는지 봅니다. 아래 항목은 모두 미검증입니다.

1

그리기

빈 공간과 카드 위에 시험용 선을 그립니다. 카드가 선택되거나 움직이지 않아야 합니다.

2

화면 이동·확대

Space/휠 조작 후에도 그림과 카드의 상대 위치가 유지되어야 합니다.

3

카드 조작으로 복귀

Selection Tool을 고르면 카드 선택·이동이 다시 되어야 합니다.

4

저장·재실행

Canvas를 닫고 Obsidian을 재시작해도 같은 그림이 돌아와야 합니다.

확인 대상사용자가 볼 결과현재 상태
전체 Canvas별도 그림판 없이 현재 Canvas의 빈 공간·카드 위에서 그리기미검증
카드 입력 충돌그리는 동안 카드가 선택·이동되지 않음미검증
조작 전환Selection Tool에서 기존 카드 선택·이동 복귀미검증
좌표와 화면이동·확대·축소 후에도 카드와 그림의 상대 위치 유지미검증
저장과 복원Canvas 전환·앱 재시작 후 원래 그림 표시미검증
데이터 분리그림 획 수만큼 Canvas Node가 늘어나지 않음미검증
기본 성능그리기 기능을 켜고 끈 상태의 Pan·Zoom·카드 조작 비교미검증

실행 시 Obsidian 버전, 시험 Canvas의 크기, 전후 데이터, 실제 화면 관찰 결과를 함께 기록합니다. 측정하지 않은 성능 수치는 만들지 않습니다.

05 / 관문과 다음 단계

검증 결과에 따라 다음 작업이 달라집니다

통과

후속 기획 진행

필수 Canvas 연동 항목이 실제 앱에서 모두 성립하면 기본 Drawing Engine과 남은 UX를 구체화합니다.

부분 통과

차이부터 결정

안 되는 동작이 사용자에게 어떤 영향을 주는지 보여주고 대안·재검증 조건을 정합니다.

실패

연동 방식 재검토

Canvas에서 바로 그리기나 P0 성능이 성립하지 않으면 고급 브러시 개발로 넘어가지 않습니다.

판정 불가

증거 보완

실행 환경이나 관찰 증거가 부족한 상태입니다. 통과로 간주하지 않습니다.

Canvas 연동 검증→기본 그리기 구조→레이어·선택·브러시→색 혼합 별도 검증→최종 지원 범위

이 화살표는 기능 간 의존 관계입니다. 각 항목이 이미 구현되었다는 표시가 아닙니다.

06 / 사용자 결정과 남은 확인

핵심 사용 흐름은 정해졌습니다

아래는 사용자가 선택한 결과입니다. 실제 Obsidian에서 가능한지, 데이터가 안전하게 이어지는지는 아직 검증 전입니다.

사용자 결정

휴지통에서 함께 복원

작업.canvas를 삭제했다가 Obsidian 휴지통에서 복원하면 카드와 그림이 함께 돌아옵니다.

사용자 결정

그림 선택은 별도 도구

카드는 Selection Tool로 움직입니다. 그림 일부를 옮길 때는 왼쪽 도구 막대의 사각형 또는 올가미를 고릅니다.

사용자 결정

그림은 카드 앞에 표시

카드 위에 그린 선은 카드보다 앞에 보입니다. 그림 레이어끼리의 순서는 기존 기획대로 조정합니다.

사용자 결정

플러그인을 꺼도 그림 보존

플러그인을 끄거나 제거해도 그림 데이터는 남습니다. 다시 켜거나 설치하면 같은 그림이 다시 보여야 합니다.

첫 대상과 다음 검증
첫 사용 버전은 Windows용 Obsidian Desktop을 우선합니다. Canvas 화면 연동, 휴지통 복원, 플러그인 재설치 후 그림 복원, 대형 Canvas 성능은 독립 Sandbox에서 확인해야 합니다.
P1 · 후속 기획
플러그인이 꺼진 동안의 화면 안내, 다른 플러그인과의 충돌 범위, 고급 색 혼합의 품질·성능은 후속 검토 대상입니다.
