# Canvas 연동 첫 실험 결과 — 2026-09-27

## 판정

후속 결정: 사용자는 2026-09-27에 기획 단계의 시험 범위를 줄이는 데 동의했다. 아래 시험 결과는 유지하고, 상세 성능·삭제 정리 검증은 해당 기능 개발 단계로 보류한다. 현재 근거를 바탕으로 색 혼합 등 기능 기획을 진행한다.

**부분 통과.** Windows의 독립 Obsidian Sandbox에서 기존 Canvas 위에 그림을 그리는 핵심 사용 흐름은 실제로 작동했다. 그러나 큰 Canvas의 반응성과 Windows 시스템 휴지통에서 영구 삭제될 때 그림 데이터를 정리하는 방법은 아직 합격 판정을 내릴 수 없다. 이 결과는 시험용 플러그인의 가능성 확인이며 제품 구현 완료가 아니다.

시험 환경: Windows, Obsidian 1.12.7 및 재시작 뒤 1.13.7, `CanvasDrawingSandbox-20260927`. 원본 Vault는 변경하지 않았다. 시험용 플러그인과 증거는 `../poc/`에 있다.

시험용 화면에는 `선택`·`그리기` 두 버튼과 한 종류의 분홍색 선만 있다. 최종 도구 막대, 올가미, 브러시, 레이어, Undo, 플러그인 제거·재설치는 시험하지 않았다. 한 화면에 Canvas를 여러 개 나란히 열었을 때 그림 표시도 검증 대상이다.

## 큰 Canvas 측정의 한계

카드·이미지 151개, 12개 점으로 구성된 선 1,500획, 그림 파일 약 458KB인 인공 시험 자료를 사용했다. 같은 Obsidian 실행에서 기능을 끄고 켠 상태로 1.2초 화면 이동을 각각 3번 측정했다. 화면 갱신 간격의 95백분위수는 끈 상태에서 41.6–55.2ms, 켠 상태에서 49.2–69.3ms였다. 끈 상태는 61–69프레임, 켠 상태는 51–56프레임이었다. 짧은 반복 시험이므로 제품 성능 수치로 일반화할 수 없지만, 기능을 켰을 때의 반응 저하 가능성을 보여준다. 메모리 단일 시점 값은 비교 근거로 삼지 않는다.

획마다 화면 요소를 만드는 첫 방식은 더 느렸다. 단일 그림 화면 방식으로 개선했지만 기본 성능 기준을 확실히 충족했다고 볼 근거는 아직 없다. 다음 실험에서는 일반 확대율과 전체 보기 상태를 나누고, 실제 그리기·카드 이동·저장을 포함해 반복 측정해야 한다.

## 데이터 정리에서 남은 문제

사용자가 Windows 휴지통에서 `작업.canvas`를 복원하면 그림도 돌아와야 한다. 이번 시험은 그림 파일을 Vault에 남겨 둔 채 Canvas만 휴지통에 보내 이 결과를 만들었다. 사용자가 Windows 휴지통을 비워 Canvas를 영구 삭제해도 그림 파일이 남는 방식이므로, 기존 기획의 `Canvas 삭제 → 연결된 그림 데이터 삭제`와 충돌한다. 영구 삭제를 안전하게 알아내고 그림 데이터를 정리하면서 복원 가능성을 유지할 방법을 후속 검증에서 정해야 한다. 내부 `.trash` 경로는 시험용 구현에서 함께 이동·복원이 됐지만, 폴더가 중첩되거나 같은 이름의 파일이 있는 경우는 아직 시험하지 않았다.
