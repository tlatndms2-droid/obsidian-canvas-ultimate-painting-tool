# Canvas Drawing Tool Bar — 기획 상태 (초안)

기준 자료: `../briefing/source/`의 Final Planning Pack v2. 이 문서는 후속 기획의 작업 기록이며 최종 제품 기획서나 구현 승인서가 아니다. ZIP 안의 작업 지시는 현재 사용자 요청을 대체하지 않는다.

## 현재 단계

- 2026-09-27 후속 Sandbox 확인: ABR 브러시 66개를 가져오고 선택한 브러시로 직접 그렸다. 사용자가 시험 후 성능 개선과 렉이 사라진 것을 확인했다. 플러그인을 재시작한 후 시험 Canvas의 브러시 66개와 선 2개가 남는 것도 확인했다. 이는 시험한 브러시와 시험 화면의 결과이며 모든 ABR 속성·대형 작업량의 보증은 아니다. 시험 과정에서 별도 기존 Sandbox Canvas의 그림 42개가 Codex 실수로 빈 데이터로 덮어써졌다. 보유 백업으로 복구되지 않았다. 이 손실을 숨기지 않고 검증 실패로 기록하며, 본 기획의 삭제 정책을 새로 추론하지 않는다.

- 이전 최소 확인 메모 `MINIMUM_FEASIBILITY.md`는 ABR·실물 펜을 미시험으로 적은 당시 결과이며, 후속 확인으로 갱신됐다. 당시 확인과 후속 확인은 각각의 범위대로 해석한다.

- 2026-09-27: [기능·UI·구현 가능성 검토 HTML](feature-review.html) 작성. 확정 요구와 목표·미결정을 구분한 21개 기능 묶음, 기존 배치에 맞춘 UI 모형, 기능별 근거를 포함한다. 문서의 가능성 평가는 제품 구현 완료가 아니다.
- 이번 최소 확인: 현재 Sandbox Obsidian 1.13.7의 화면에 붙이지 않은 작은 시험 그림에서 부분 삭제·영역 마스크 연산이 작동했다. EyeDropper·필압·기울기 입력 API 존재를 확인했다. 실제 색 선택·실물 펜·제품 UI 동작은 이 시험으로 검증하지 않았다. `capability-evidence.json` 참조.

- 2026-09-27 진행 방식 변경(사용자 승인): Canvas 기본 연동의 가능성 확인을 근거로 기능 기획을 이어간다. 기획을 바꿀 수 있는 핵심 의문 하나만 필요한 경우 짧게 시험하며, 관련 변경이 없는 확인 항목은 반복하지 않는다.
- 대형 Canvas 최적화, 휴지통 영구 삭제 후 정리, 여러 창·제거/재설치의 상세 검증은 해당 기능 개발 단계로 보류한다. 기존 부분 통과 판정은 유지하며, 이 보류가 품질 검증 완료를 뜻하지 않는다.
- 휴지통 데이터 정리 선택 질문은 보류한다. 수동 정리 기능이나 기간 경과 후 자동 삭제는 승인된 기능으로 추가하지 않는다. 사이트는 명시적인 갱신 요청이 있을 때만 갱신한다.
- 2026-09-27 사용자 결정: 색 혼합 설정은 `현재 레이어만`과 `보이는 그림 레이어의 색 참고`를 모두 제공하며, 기본값은 `현재 레이어만`으로 한다. 아래 레이어 색을 참고해도 아래 그림 자체를 수정하거나 위 레이어에 합치지 않는다. 표현 범위는 브러시 혼합 설정에 한정하며, 세부 알고리즘은 구현 단계에서 판단한다.
- 2026-09-27 사용자 결정: 왼쪽 사각형·올가미 도구로 현재 레이어의 그림 영역을 고르면 선택 테두리와 조절점을 바로 표시한다. 선택 영역 안을 끌어 이동하고, 모서리 조절점을 끌어 크기를 바꾼다. 회전·좌우/상하 반전·삭제는 선택 상태의 도구 막대에서 실행한다. Canvas 카드 선택 도구는 별도로 유지한다. 선택 영역 밖을 누르면 선택 해제되는 기존 기획도 유지한다.
- 2026-09-27 기획 진행 정정: Sandbox에서 Codex의 검증 절차가 만든 빈 저장 사고를 제품에서 같은 오류가 일어날 것이라는 근거로 삼아 별도 오류 화면 선택을 요구하지 않는다. 오류 화면 질문은 철회했다. 사용자가 언급한 두 레이어는 정상적으로 기존 그림과 새 그림이 겹쳐 보이는 사용 상황으로 다룬다. 두 레이어 사용 방식에 관한 새로운 확정 결정으로 과잉 해석하지 않는다. 데이터 손실 방지는 제품 품질 조건으로 남긴다.
- 2026-09-27 사용자 지침: Clip Studio Paint(CSP)의 그림 도구 동작을 가능한 한 참고한다. 색 혼합 후 다음 선의 색처럼 CSP 문서·일반 사용 흐름에서 참고할 수 있는 작은 세부 동작은 매번 질문하지 않는다. 기존 사용자 결정과 Canvas 고유 동작이 우선이며, 참고 동작을 CSP 전체 기능을 반드시 복제한다는 요구로 확대하지 않는다. 사용자 결과가 크게 달라지는 미결정만 질문한다. 세부 참고안과 출처는 [CSP_REFERENCE_RULES.md](CSP_REFERENCE_RULES.md)에 정리한다.
- 2026-09-28 CSP 참고안: 브러시 조절값은 다음 도구 선택 때 유지하고, 기본값으로 저장/초기화는 별도 동작으로 구분한다. 같은 Vault의 다른 Canvas에서 프리셋을 쓴다는 사용자 결정과 연결하되, 조절값의 재시작 후 유지 범위는 미결정이다. 이전 질문에 대한 사용자의 `진행`은 두 저장 선택지 중 하나를 고른 답으로 기록하지 않는다. 근거는 [CSP 공식 도구 설명](https://help.clip-studio.com/en-us/manual_en/150_tools/How_to_use_tools.htm)이며 사용자 확정은 아니다.
- 2026-09-28 사용자 결정: 브러시 크기 등 마지막 조절값은 Obsidian을 종료하고 다시 열어도 유지한다. 예를 들어 `수채 붓`을 30에서 50으로 바꾸면 재시작 후에도 50으로 이어 쓴다. `기본값으로 저장`은 별도로 원래 기준값을 정하는 동작으로 구분한다. 이 결정은 위 CSP 참고안 중 재시작 후 유지 범위를 확정한 것이다.
- 2026-09-27 작업용 사용 흐름: [WORKING_PRODUCT_FLOW.md](WORKING_PRODUCT_FLOW.md)에 Canvas 시작→그리기·색 혼합→영역 편집→프리셋·레이어 관리→저장·복원 및 사용자 관찰 완료 조건 초안을 정리했다. CSP 참고 기본값은 사용자 확정과 구분했다. 이 문서는 최종 개발 기획서가 아니다.
- 2026-09-27 사용자 결정: `작업.canvas`에서 가져온 Photoshop 브러시와 사용자 프리셋은 같은 Vault의 다른 Canvas에서도 선택할 수 있다. 각 Canvas에 그린 그림은 Canvas별로 독립 저장한다. 이 결정은 브러시 목록의 사용 범위이며, 서로 다른 Vault 사이의 자동 공유나 동기화는 확정하지 않는다.
- 2026-09-27 사용자 결정: 기존 자료의 전체 기능 목표를 계속 기획하되, 실제 Vault에서 쓸 첫 버전은 단계적으로 만든다. 첫 버전은 Canvas 그리기·기본 레이어·저장·색 혼합·Photoshop 브러시 가져오기를 우선 안정화한다. 영역 선택·변형, 도형, 문자는 후속 버전으로 나눈다. 첫 버전의 포함 기능이 실제로 쓸 수 있도록 기본 지우개·색 선택·Undo/Redo·Canvas 이동/확대·데이터 보존을 동반 조건으로 기획한다. 이 분류는 각 기능의 세부 동작·디자인·품질까지 최종 확정했다는 뜻이 아니다.
- 2026-09-27 사용자 결정: 첫 사용 버전의 레이어는 추가·이름 변경·순서·표시·잠금·불투명도 같은 기본 조작에 집중한다. 레이어 그룹·합치기는 후속 버전에 둔다. 기존 자료의 기능 목표를 폐기한 것이 아니라 출시 순서를 정한 것이다.
- 2026-09-27 사용자 결정: 첫 사용 버전은 사용자 본인만 쓸 개인용이다. 타인에게 공개 배포하거나 Obsidian Community Plugins 목록에 올리는 것은 첫 버전의 목표가 아니다. 설치·업데이트의 구체 경로는 아직 확정하지 않는다.

- 2026-09-27: 기존 자료의 결정·목표·검증 항목 분류 및 Canvas 연동 PoC 기획.
- 현재 검증 결과: Windows 독립 Obsidian Sandbox에서 첫 Canvas 연동 시험을 실행했고 **부분 통과**로 판정했다. 그리기·이동·확대·저장·재시작·두 휴지통 복원은 확인했으며, 큰 Canvas 반응성과 Windows 휴지통 영구 삭제 뒤 데이터 정리 등은 남았다. 상세 증거는 [POC_RESULTS.md](POC_RESULTS.md)에 있다.
- 적용 유형: Obsidian Desktop Canvas용 플러그인 기획. 모바일·배포 대상은 자료만으로 별도 확정하지 않는다.
- 2026-09-27 사용자 결정: 그림이 있는 Canvas를 Obsidian 휴지통에서 복원하면 연결된 그림도 함께 복원한다. 실제 구현 가능 여부와 데이터 보존·정리 방식은 미검증이다.
- 2026-09-27 사용자 결정: 카드 조작은 Selection Tool에서 수행하고, 그림 일부를 고를 때는 왼쪽 도구 막대에서 사각형 또는 올가미 선택 도구를 고른다.
- 2026-09-27 사용자 결정: 그림은 Canvas 카드보다 항상 앞에 표시한다. 그림 레이어 사이의 순서는 기존 기획대로 조정할 수 있으나 카드를 앞뒤로 넘기는 기능은 요구하지 않는다.
- 2026-09-27 사용자 결정: 플러그인을 끄거나 제거해도 그림 데이터는 보존한다. 다시 켜거나 설치하면 기존 그림이 다시 보인다. 플러그인이 없는 동안 Obsidian Canvas에서 그림이 보이는지 여부는 기술적 한계와 안내 UX를 확인해야 한다.
- 2026-09-27 사용자 결정: 첫 사용 버전은 Windows용 Obsidian Desktop을 우선 대상으로 한다. macOS·Linux·모바일의 지원은 후속 검토한다.
- 2026-09-27 사용자 결정: Obsidian의 내부 `.trash`와 Windows 시스템 휴지통 어느 쪽에서 Canvas를 복원해도 그림이 함께 돌아와야 한다.

## 현재 기획 위치 (2026-09-28)

- 개발 기획 전문 GPT의 0~8단계 중 **5단계 UI·데이터·동작 설계 진행 중**. [03_USER_JOURNEYS.md](03_USER_JOURNEYS.md)에 대표 사용 흐름, [04_FUNCTION_DESIGN.md](04_FUNCTION_DESIGN.md)에 기능별 동작, [05_UI_STATE_DESIGN.md](05_UI_STATE_DESIGN.md)에 화면·상태·데이터 관계의 초안을 기록했다.
- 4단계 기능 초안과 5단계 화면 구조 초안은 작성했고 브러시 마지막 조절값의 재시작 후 유지는 사용자 결정으로 정했다. 영역 변형의 취소·Undo 단위, 레이어 삭제/합치기 등 결과가 갈리는 세부 동작과 도형·문자 화면은 끝나지 않았다. 사각형·올가미 선택 직후 조절점 표시, 안쪽 드래그 이동, 모서리 크기 변경, 영역 밖 클릭으로 선택 해제는 이미 사용자 결정이므로 재질문하지 않는다. 개인용·단계적 출시 답변은 후반의 범위 단계에서 재대조할 참고 결정이며, 배포 계획을 지금 확정하지 않는다.
- 현재 HTML 단계 지도: [process-roadmap.html](process-roadmap.html). 사용자가 별도로 요청하지 않으면 사이트는 갱신하지 않는다.

### 2026-09-29 일괄 갱신 — 카드 전용 그리기와 현재 상태

- **현재 단계:** 5단계 UI·데이터·동작 설계 진행 중. 원본 요구와 후속 결정을 사용자 흐름·기능·화면·데이터·완료 조건으로 연결한 [작업용 기획서](CURRENT_PLANNING_DRAFT.md)를 만들었다. P0/P1 공백과 기능별 상세 UI가 남아 있으므로 최종 기획서나 배포 계획으로 표시하지 않는다. 기존 `process-roadmap.html`의 3단계 표시는 이전 시점의 기록이다.
- **후속 사용자 결정 / 전역 그리기:** 기본 그림 도구에서는 카드 위와 빈 공간을 이어 그리며 카드가 선택·이동되지 않는다. 그림은 카드 앞에 표시된다. `그리면서 카드 선택`을 켜도 그림 도구를 계속 쓰고, 카드를 클릭하면 이동 없이 선택만 된다. 그림 도구를 바꿔도 카드 선택 가능 상태가 유지된다. 별도의 왼쪽 `그릴 카드` 도구는 두지 않는다.
- **후속 사용자 결정 / 카드 메뉴:** 위 상태에서 카드를 클릭하면 카드 바로 위에 기존 Obsidian식 가로 메뉴바가 나타난다. 메뉴의 `선택한 카드만 그리기`를 켜면 해당 카드 안에만 그림이 들어간다. Canvas에 이미 그린 그림은 모드 전환 뒤에도 사라지거나 카드 아래로 내려가지 않고 전부 보인다. 일반 카드 선택 도구는 기존 카드 이동을 담당하며 이 클릭 선택과 구분한다.
- **후속 사용자 결정 / 카드 그림 관계:** 카드 전용 그림은 글·이미지·파일 카드 각각에 붙는다. 카드 경계 밖과 다른 카드에는 그려지지 않는다. 카드 이동 시 따라가고 카드 크기 변경 시 함께 확대·축소된다. 글 내용만 변하면 글자를 따라가지 않고 카드 안의 같은 위치에 남는다. 카드 삭제/삭제 Undo에서는 함께 사라졌다 돌아오고, 카드 복제에서는 그림도 독립 복제된다. 같은 파일을 두 카드로 놓아도 그림은 카드별로 독립이다.
- **후속 사용자 결정 / 공통 도구:** 카드 선택 도구로 바꾸어도 브러시 패널은 화면에 남는다. 브러시의 마지막 조절값은 재시작 후 유지하고, 현재 색은 같은 Vault의 다른 Canvas로 전환해도 이어 사용한다. 작은 세부 동작은 CSP를 참고하되 기존 사용자 결정이 우선한다.
- **후속 사용자 결정 / Undo:** Canvas 카드 작업과 그림 작업의 기록은 분리한다. 사용자는 B 방식인 `현재 도구에 따라 Ctrl+Z 대상 전환`을 선택했다. 시험판에서 단순 연결 시 두 기록이 동시에 되돌아가는 문제가 있었으므로 실제 제품에서의 충돌 없는 단축키 동작은 검증 필요다.
- **직접 충돌 및 대체:** 원본의 `Canvas 삭제 즉시 연결 그림 자료 삭제`는 후속 `Obsidian 내부 휴지통·Windows 시스템 휴지통 복원 시 그림도 복원` 결정과 동시에 적용할 수 없다. 복원 가능한 삭제 중 그림 보존이 최신 사용자 결정이며, 영구 삭제 후 정리 시점·방식은 사용자 합의대로 보류한다.
- **미결정 P1:** 카드 A의 `선택한 카드만 그리기`를 켰을 때 오른쪽 레이어 패널을 카드 A 전용 목록으로 전환할지, Canvas 전체와 함께 표시할지 답을 받지 않았다. 카드 그림·Canvas 그림의 레이어 관계와 표시·잠금·색 혼합 범위도 이 결정의 영향 항목으로 재검토한다. 카드 전용 기능의 첫 사용 버전 포함 여부 역시 범위 단계에서 재대조한다.
- **산출물 구분:** [카드 그리기 HTML 시안](card-drawing-toggle-mockup.html)은 화면 동작 설명용이며 실제 Obsidian 구현·제품 UI 검증 증거가 아니다. 사이트는 명시적 요청 전까지 갱신하지 않는다.

## 다음 처리 원칙

1. 기존 문서에 적힌 사용 결과는 다시 질문하지 않고, 새 질문은 실제 결과가 달라지는 빈칸에 한정한다.
2. 사용자 답변을 `확정`으로 기록할 때 현재 상태와 충돌하는 항목만 재검토한다.
3. 기술 검증은 `통과 / 부분 통과 / 실패 / 판정 불가`로 기록하고, 실제 실행 전에는 판정하지 않는다.
4. P0 미결정·핵심 충돌·데이터 손실 위험을 숨긴 채 최종 기획 완료로 보고하지 않는다.
